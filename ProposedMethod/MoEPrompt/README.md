# MoEPrompt: mixture-of-experts missing-modality generator for MPLMM

Extension of the MPLMM baseline (`../MPLMM`, used read-only; nothing is
imported from `../RAGPrompt`). In MPLMM a missing modality is generated by
**one fixed function for every sample**, trained only through the task loss.
Two changes:

* **H2: mixture of experts.** A router gives every sample its own weights over
  K light experts; their mix is added to the baseline generator, which acts as
  an always-on shared expert.
* **H1: reconstruction + distillation.** In training the "missing" modality is
  still in the batch (missingness is only a mode code), so the generator can be
  supervised directly.

## Model

```
sample x, modality m missing, available sources S
  │
  ├─ baseline generator (unchanged) ─────────────────────────► G_base(x)[m]
  │
  ├─ experts k = 1..K: for each available source s
  │     LayerNorm → Linear(D_s→r) → GELU → Linear(r→30)   (low rank, per time step)
  │     → resample to the length of m (avg-pool / interpolate)
  │     → mean over available sources ───────────────────► expert_k(x)[m]
  │
  └─ router: time-mean of each AVAILABLE modality (missing ones zeroed)
             + missing-mode embedding → MLP → softmax ───────► p_k(x)[m]

x_hat[m] = G_base(x)[m] + tanh(gate_m) · Σ_k p_k(x)[m] · expert_k(x)[m]      (gate_m starts at 0)
```

Rest of MPLMM unchanged (frozen MOSEI backbone, same prompts and head).

**Expert weights with K = 3.** They are not fixed: the router computes them per
sample and per missing modality. At initialisation every sample gets exactly
(1/3, 1/3, 1/3). Training (task + reconstruction + distillation) moves them;
a load-balancing loss keeps the *batch average* near 1/3 each so that no
expert dies, while single samples may still route sharply. `train_moe.py`
prints the mean weights and entropy per case at the end of each MoE run.

## Losses

`loss = task + λ_rec · rec + λ_kd · kd + λ_bal · balance`

| term | definition |
|---|---|
| `rec` | log(1 + NMSE) between generated x_hat[m] and the real `proj_m(x_m)` (detached), per missing modality |
| `kd` | NMSE between the representation before the output layer and that of the same model on the complete sample (eval mode, no grad) |
| `balance` | KL(batch-mean router weights ‖ uniform), per generated modality (MoE only) |

NMSE = ‖pred − target‖² / ‖target‖² (scale-free; 1 = as bad as predicting 0).
The best checkpoint is still chosen on the **validation task loss**.

## Layout

| Path | Purpose |
|---|---|
| `moemm/config.py` | paths, dataset settings, baseline checkpoints, missing-modality cases |
| `moemm/bridge.py` | the only file that imports MPLMM code |
| `moemm/data.py` | MPLMM loaders, seeded shuffling |
| `moemm/experts.py` | `Translator`, `Router`, `MoEGenerator` |
| `moemm/model.py` | `MoEPromptModel(PromptModel)`, checkpoint save/load |
| `moemm/losses.py` | reconstruction, distillation, load balance |
| `moemm/evaluate.py` | 6-case ACC / weighted F1 (baseline conventions), routing table |
| `scripts/diagnose.py` | Stage 0: oracle (real features) and zero ablation of the baseline generator |
| `scripts/sanity_checks.py` | correctness checks (must print ALL CHECKS PASSED) |
| `scripts/train_moe.py` | one run → `results/runs.csv` (+ `results/routing/<run>.csv`) |
| `MoEExperiments.ipynb` | runs the scripts and builds the tables |

Generated (gitignored): `checkpoints/`.

## Run

```bash
cd MoEPrompt
python scripts/diagnose.py      --dataset mosi
python scripts/sanity_checks.py --dataset mosi
python scripts/train_moe.py     --dataset mosi --moe 0                                   # reference
python scripts/train_moe.py     --dataset mosi --moe 0 --lambda_rec 0.5 --lambda_kd 0.5  # H1
python scripts/train_moe.py     --dataset mosi --moe 1                                   # H2
python scripts/train_moe.py     --dataset mosi --moe 1 --lambda_rec 0.5 --lambda_kd 0.5  # H1 + H2
```

No dependencies beyond the baseline's (torch, numpy, scikit-learn, pandas, h5py).

## Verified before training (all 4 datasets)

* the table-driven generator reproduces the baseline table exactly (MOSI 62.22 / 58.23);
* MoE off and MoE with gate 0 give **bit-identical** outputs to the baseline `PromptModel` in all 7 modes;
* replacing a missing modality's content with noise changes **nothing** (no leakage), with the gate open;
* router weights sum to 1 and are exactly 1/3 at initialisation;
* one reconstruction pair per missing modality, targets detached, teacher without gradient;
* with the gate at 0 only the gate gets gradient from the MoE branch; once open, every expert does; the frozen backbone (1,061,280 parameters) never does;
* end-to-end smoke runs (train → checkpoint → reload → evaluate → routing report) on MOSI and IEMOCAP.
